## Data Model

Agent ◄──────────────── Order
  ▲                       ▲

---

### `Agent`
**Table:** `agents`  
**ID type:** `String` (e.g. `"A1"`)

| Field | Type | Notes |
|---|---|---|
| `id` | `String` | Primary key, manually assigned |
| `name` | `String` | Agent display name |
| `activeOrderCount` | `int` | Defaults to `0`; used for load-balancing |
| `status` | `AgentStatus` | Current availability state |
| `orders` | `List<Order>` | Lazy-loaded; mapped by `assignedAgent` |

**Status enum — `AgentStatus`**

| Value | Meaning |
|---|---|
| `AVAILABLE` | Agent can receive new orders |
| `BUSY` | Agent is at capacity |
| `OFFLINE` | Agent is unreachable — triggers the T-4 agentic re-planning loop |

---

### `Order`
**Table:** `orders`  
**ID type:** `String` (e.g. `"O1"`)

| Field | Type | Notes |
|---|---|---|
| `id` | `String` | Primary key, manually assigned |
| `description` | `String` | Free-text order details (stored as TEXT) |
| `status` | `OrderStatus` | Current lifecycle state |
| `createdAt` | `LocalDateTime` | Auto-set via `@PrePersist` |
| `assignedAgent` | `Agent` | FK → `agents.id`; nullable (unassigned orders) |

**Status enum — `OrderStatus`**

| Value | Meaning |
|---|---|
| `ASSIGNED` | Order has an agent |
| `REASSIGNMENT_PENDING` | A `ReassignmentSuggestion` exists and awaits ops approval |
| `REASSIGNED` | Ops accepted a suggestion; order belongs to the new agent |
| `DELIVERED` | Order is complete |

---

### `ReassignmentSuggestion`
**Table:** `reassignment_suggestions`  
**ID type:** `Long` (auto-generated)

| Field | Type | Notes |
|---|---|---|
| `id` | `Long` | Auto-generated primary key |
| `order` | `Order` | FK → `orders.id`; the order needing reassignment |
| `recommendedAgent` | `Agent` | FK → `agents.id`; nullable if AI returned invalid ID |
| `confidence` | `Double` | LLM confidence score, clamped to `[0.0, 1.0]` |
| `reasoning` | `String` | Plain-English LLM rationale shown in the ops UI |
| `status` | `SuggestionStatus` | Lifecycle state (default: `PENDING`) |
| `triggerReason` | `TriggerReason` | What caused this suggestion to be created |
| `createdAt` | `LocalDateTime` | Auto-set via `@PrePersist`; immutable after insert |
| `resolvedAt` | `LocalDateTime` | Set when ops accepts or rejects; null while PENDING |

**Composite index:** `(order_id, status, trigger_reason)` — used by the T-4 idempotency check.

**Status enum — `SuggestionStatus`**

| Value | Meaning |
|---|---|
| `PENDING` | Awaiting ops action in the dashboard |
| `ACCEPTED` | Ops approved — order moved to `recommendedAgent` |
| `REJECTED` | Ops rejected — order stays unchanged |

**Trigger enum — `TriggerReason`**

| Value | Meaning | UI Badge |
|---|---|---|
| `INITIAL` | Created at order creation or via manual API call | None |
| `AGENT_OFFLINE` | Auto-generated by T-4 loop when agent goes `OFFLINE` | `AGENTIC` |

**Domain invariant:** at most one `PENDING` + `AGENT_OFFLINE` suggestion may exist per order at a time (enforced in the T-4 service layer).

**Domain method — `resolve(SuggestionStatus)`**  
Always sets `status` and `resolvedAt` together so callers cannot forget the timestamp.

## Repository Layer

| Repository | Entity | Custom queries |
|---|---|---|
| `AgentRepository` | `Agent` | `findByStatus`, `findByActiveOrderCountLessThan`, `findByStatusOrderByActiveOrderCountAsc` |
| `OrderRepository` | `Order` | `findByAssignedAgentId`, `findByStatus`, `findByAssignedAgentIdAndStatus` |
| `ReassignmentSuggestionRepository` | `ReassignmentSuggestion` | `findByOrderId`, `findByStatus`, `findByOrderIdAndStatusAndTriggerReason` (idempotency), `findByRecommendedAgentId` |

All repositories extend `JpaRepository` and inherit `save`, `findById`, `findAll`, `delete`, `count` for free.

---

## Key Design Decisions

- **Lombok** (`@Getter`, `@Setter`, `@NoArgsConstructor`, `@ToString`) is used on all entities to eliminate boilerplate. The parameterised convenience constructors, `@PrePersist` hooks, and domain methods are written manually.
- **Lazy fetching** is used on all `@ManyToOne` and `@OneToMany` relations to avoid N+1 queries.
- **`@ToString(exclude = "orders")`** on `Agent` prevents triggering the lazy collection during logging.
- **Rich entity model** — `ReassignmentSuggestion.resolve()` enforces its own state-transition invariant rather than relying on the service layer.
